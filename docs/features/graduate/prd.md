# Product Requirements Document (PRD)
## Feature: Graduate Meditation Credit & Approval System (`graduate`)
**ระบบลงทะเบียนและสะสมวันปฏิบัติกรรมฐาน ระดับบัณฑิตศึกษา (Laravel 11 Edition)**
ครอบคลุม 52 ส่วนงานทั่วประเทศ มหาวิทยาลัยมหาจุฬาลงกรณราชวิทยาลัย (MCU)

---

### 1. วัตถุประสงค์ของระบบ (Objective)
1. **การบริหารเกณฑ์หลักสูตรบัณฑิตศึกษา:** รองรับระเบียบมหาวิทยาลัยมหาจุฬาลงกรณราชวิทยาลัย ว่าด้วยการปฏิบัติวิปัสสนากรรมฐานสำหรับนิสิตระดับบัณฑิตศึกษา
   - **ระดับปริญญาโท:** สะสมวันปฏิบัติธรรมครบ **30 วัน**
   - **ระดับปริญญาเอก:** สะสมวันปฏิบัติธรรมครบ **45 วัน**
2. **ระบบสะสมวันและยื่นคำขอแบบเบ็ดเสร็จ (One-Time Final Submission):** ให้นิสิตสามารถบันทึกประวัติการเข้าปฏิบัติธรรมย่อยทีละครั้ง พร้อมแนบหลักฐาน (ใบประกาศ / หนังสือรับรอง) โดยระบบจะล็อกปุ่มยื่นคำขอจนกว่าจะสะสมครบตามเกณฑ์
3. **เวิร์กโฟลว์การตรวจสอบและอนุมัติ (Multi-tier Verification Workflow):** เพิ่มประสิทธิภาพให้เจ้าหน้าที่บัณฑิตศึกษาและคณะกรรมการตรวจสอบเอกสารผ่านหน้าจอแบบ Split-Screen Reviewer สามารถสั่งอนุมัติ หรือส่งกลับแก้ไขพร้อมระบุเหตุผลได้ทันที
4. **ความน่าเชื่อถือและการสำเร็จการศึกษา:** ออกรหัสรับรองการผ่านเกณฑ์ (Digital Completion Code / Verification Slip) เพื่อให้สำนักทะเบียนและประมวลผล (Registrar) นำไปตรวจสอบประกอบการอนุมัติปริญญาบัตร

### 2. กลุ่มผู้ใช้งาน (User Personas & Roles)

| กลุ่มผู้ใช้ (Persona) | บทบาทและขอบเขตหน้าที่ในระบบ | ความต้องการหลัก (Pain Points & Needs) |
| :--- | :--- | :--- |
| **นิสิตระดับปริญญาโท/เอก** (`STUDENT_GRAD`) | - ค้นหาประวัติด้วยรหัสนิสิต<br>- บันทึกประวัติการเข้าปฏิบัติธรรมแต่ละครั้ง<br>- อัปโหลดไฟล์หลักฐาน (PDF/JPG/PNG)<br>- ตรวจสอบความคืบหน้า (Progress Gauge)<br>- ยื่นขออนุมัติเมื่อวันสะสมครบตามเกณฑ์ | ต้องการเห็นความคืบหน้าที่ชัดเจน (เช่น สะสมแล้ว 35/45 วัน ขาดอีก 10 วัน) และไม่อยากเสียเวลาเดินทางมายื่นเอกสารกระดาษที่มหาวิทยาลัย |
| **เจ้าหน้าที่บัณฑิตศึกษา** (`GRAD_STAFF`) | - คัดกรองและตรวจสอบความถูกต้องของวันและสถานที่<br>- พรีวิวไฟล์หลักฐานโดยไม่ต้องดาวน์โหลดลงเครื่อง<br>- ส่งกลับให้นิสิตแก้ไขพร้อมบันทึกหมายเหตุ | ต้องการระบบคำนวณวันอัตโนมัติ และฟังก์ชัน Split-Screen ตรวจเอกสารแนบได้อย่างรวดเร็ว |
| **คณะกรรมการ / ผู้มีอำนาจอนุมัติ** (`GRAD_APPROVER`) | - อนุมัติผลการผ่านเกณฑ์ในขั้นตอนสุดท้าย<br>- เพิกถอนหรือส่งเรื่องทบทวนกรณีตรวจพบข้อผิดพลาด | ต้องการระบบที่ล็อกเอกสารไม่ให้แก้ไขระหว่างรออนุมัติ และบันทึก Audit Log ชัดเจนว่าใครเป็นผู้อนุมัติ |
| **นายทะเบียนส่วนกลาง** (`REGISTRAR`) | - ค้นหาและตรวจสอบสถานะการผ่านเกณฑ์รายบุคคล<br>- ส่งออกรายงานรายชื่อนิสิตที่ผ่านเกณฑ์ (Graduation Clearance) | ต้องการรหัสตรวจสอบ (Verification Code) ที่ตรวจสอบย้อนกลับได้ และส่งออกไฟล์ Excel/PDF ได้ถูกต้อง |

### 3. Functional Requirements และ Use Cases

#### 3.1 นิสิตบันทึกประวัติย่อย (Credit Entry Recording)
- **UC-01:** นิสิตสามารถเพิ่มรายการปฏิบัติธรรมย่อย ประกอบด้วย:
  - สำนักปฏิบัติธรรม / วัด / ส่วนงานที่เข้าร่วม
  - พระวิปัสสนาจารย์ / ผู้รับรอง
  - จังหวัดที่ตั้ง
  - วันที่เริ่มต้น - วันที่สิ้นสุด (ระบบคำนวณจำนวนวันให้อัตโนมัติ: `(endDate - startDate) + 1`)
  - อัปโหลดไฟล์ใบรับรองหรือภาพถ่ายหลักฐาน (รองรับ PDF, JPG, PNG ขนาดไม่เกิน 10MB พร้อมจัดเก็บใน `storage/app/public/attachments/`)
- **UC-02:** นิสิตสามารถแก้ไขหรือลบรายการย่อยได้ **เฉพาะในขณะที่ยังอยู่ในสถานะ `ACCUMULATING` หรือถูกสั่ง `RETURNED_FOR_EDIT` เท่านั้น**

#### 3.2 การล็อกและยื่นคำขอขั้นสุดท้าย (Lock & One-Time Final Submission)
- **UC-03:** ระบบจะแสดง Progress Bar คำนวณวันสะสมเทียบกับเกณฑ์:
  - ปริญญาโท: `Target = 30 วัน`
  - ปริญญาเอก: `Target = 45 วัน`
- **UC-04 (Lock Engine):** ปุ่ม "ยื่นขออนุมัติผลการปฏิบัติธรรม" จะถูก **Disable/Lock ไว้อย่างเด็ดขาด** ตราบใดที่ `accumulated_days < target_days`
- **UC-05:** เมื่อวันสะสมครบ นิสิตกดยื่นคำขอ ระบบจะเปลี่ยนสถานะเป็น `SUBMITTED` และ **ล็อกห้ามแก้ไข/ลบรายการย่อยทั้งหมดทันที** เพื่อรอเจ้าหน้าที่ตรวจสอบ

#### 3.3 การตรวจสอบและพิจารณาโดยเจ้าหน้าที่ (Review & Workflow Action)
- **UC-06:** เจ้าหน้าที่บัณฑิตศึกษาเรียกดูรายการที่ยื่นเข้ามา (`SUBMITTED`) โดยกรองตาม 52 ส่วนงาน, ปีการศึกษา หรือระดับปริญญาได้
- **UC-07:** หน้าจอ Split-Screen แสดงข้อมูลประวัติการปฏิบัติธรรมทางฝั่งซ้าย และหน้าต่างพรีวิวเอกสารแนบทางฝั่งขวา
- **UC-08:** เจ้าหน้าที่สามารถดำเนินการได้ 3 รูปแบบ:
  1. **อนุมัติ (`APPROVED`):** ออกรหัส `completion_code` (รูปแบบ `MCU-GRD-YYYY-XXXXX`) และบันทึกวันที่อนุมัติ
  2. **ส่งกลับแก้ไข (`RETURNED_FOR_EDIT`):** บังคับระบุหมายเหตุ (`rejection_note`) ปลดล็อกให้นิสิตกลับไปแก้ไขเฉพาะรายการที่มีปัญหา
  3. **ไม่อนุมัติ (`REJECTED`):** ปฏิเสธคำร้องกรณีตรวจพบการทุจริตหรือไม่ตรงตามเกณฑ์หลักสูตร

#### 3.4 การตรวจสอบความถูกต้องและการออกใบรับรองดิจิทัล (Verification & Certification)
- **UC-09:** นิสิตที่ได้รับการอนุมัติสามารถเปิดหน้า Digital Completion Slip พร้อม QR Code สำหรับสแกนตรวจสอบความถูกต้องแบบสาธารณะ
- **UC-10:** เจ้าหน้าที่ทะเบียนสามารถตรวจสอบสถานะด้วย `student_code` หรือ `completion_code` เพื่อยืนยันคุณสมบัติก่อนขออนุมัติสำเร็จการศึกษา

### 4. Acceptance Criteria (เกณฑ์การตรวจรับงาน)

1. **เกณฑ์ด้านสิทธิ์และความปลอดภัย:**
   - [ ] นิสิตเข้าถึงได้เฉพาะข้อมูลของตนเอง และแก้ไขได้เฉพาะตอน `ACCUMULATING` หรือ `RETURNED_FOR_EDIT`
   - [ ] เจ้าหน้าที่ต้องผ่าน Middleware การตรวจสอบสิทธิ์การเป็น Admin
   - [ ] มีการบันทึกประวัติการกระทำสำคัญ เช่น การอนุมัติหรือส่งกลับแก้ไข
2. **เกณฑ์ด้าน Business Logic:**
   - [ ] นิสิต ป.โท ที่มีวันสะสมไม่ถึง 30 วัน หรือ ป.เอก ไม่ถึง 45 วัน **ไม่สามารถกดยื่นขออนุมัติได้ทุกกรณี** (ตรวจทั้ง UI และระดับ Controller Validation)
   - [ ] เมื่อสถานะเป็น `SUBMITTED` รายการย่อยทั้งหมดต้องไม่สามารถถูกแก้ไขหรือลบผ่าน Request ได้
   - [ ] การคำนวณวันระหว่างวันที่เริ่มต้นถึงวันที่สิ้นสุด ต้องนับรวมวันแรกและวันสุดท้ายถูกต้อง (`Inclusive`)
3. **เกณฑ์ด้านสถาปัตยกรรมและเทคโนโลยี:**
   - [ ] ทำงานเข้ากันได้ 100% กับ **Laravel 11 บน Apache/2.4 + PHP 8.4 + MariaDB 10.6**
   - [ ] ใช้ระบบไอคอน **Lucide Icons** (`data-lucide="..."`) และสไตล์สี **Earth Tones / Organic Palette**
